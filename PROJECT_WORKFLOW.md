# Open Case Ledger Project Workflow

## Outbound email preflight

Before recommending, drafting, or sending any outreach email for a case:

1. Search the Open Case Ledger Gmail account for the proposed recipient email address and agency domain.
2. Search Gmail for the case name, victim name, and any known agency case number.
3. Review recent sent messages to the same agency to avoid sending multiple records requests in close succession unless there is a clear reason.
4. Check whether another Open Case Ledger case is already open with that agency or records unit.
5. If an active request already exists with that agency, prefer rotating to a different agency/case unless the new request is time-sensitive, clearly unrelated, or specifically requested.
6. Only after this preflight should a new outreach email be recommended or drafted.

## Email drafting and signature

When the next user task is to send an email and the connected Open Case Ledger Gmail account is available:

1. Create the actual Gmail draft rather than only pasting email text into chat.
2. Give the user the direct Gmail draft link so the message can be reviewed and sent with minimal clicks.
3. Include the Open Case Ledger website link under the signature in routine project outreach: https://open-case-ledger.github.io/
4. Do not send the message yourself unless the user explicitly asks you to send it.
5. After the user says the message was sent, verify it in Sent when possible and update the master tracker.

## Tracker review before assigning work

Before assigning the user's next Open Case Ledger task, review the live master spreadsheet for unfinished, overdue, waiting, or newly actionable work rather than relying only on the most recent chat messages. Regularly scan all relevant tabs, including Request Tracker, Agency Queue, Email Log, Response Log, Dashboard, Case Master, Records Received, Today's Queue, Research Queue, Project To-Dos, Legacy Personal Email, Source Materials, and Discrepancies & Gaps.

If a maintenance item is promised for later, such as a website repair or source-preservation task, add it to Project To-Dos so it cannot disappear from the workflow. Close or supersede stale tasks when later events make them obsolete.

## Task rotation

Do not treat every next task as a new records request. Regularly rotate among:

- New outreach to a fresh agency/case
- Follow-up on an existing request when its due date or trigger arrives
- Review and logging of records already received
- Audit of older/legacy email threads for outcomes that were never captured
- Public-source timeline or evidence-gap research on an existing case
- Court/archive/local-history research that advances an existing lead
- File sorting, preservation, spreadsheet/website updates, and other project maintenance

Email work should remain the largest share of the user's tasks, but a substantial portion of those email tasks should be replies, follow-ups, routing corrections, or audits of existing threads rather than fresh initial inquiries. Avoid clustering too many consecutive new-inquiry tasks.

## Case rotation preference

Prefer rotating across different agencies and cases rather than concentrating multiple consecutive requests on one agency. Favor email-based records routes when practical to reduce portal/password overhead.

## Preferred case profile

Priority goes to cases with a realistic identification or investigative advancement pathway, especially older pre-digital or pre-DNA-era cases, LGBTQ+/trans cases, and cases in Oregon, California, Colorado, Washington, or Nevada.
